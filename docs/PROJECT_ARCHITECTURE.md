# CellFlowX Project Architecture

## Architecture Principle

CellFlowX separates:

1. immutable input data
2. workflow orchestration
3. analysis implementation
4. configuration
5. results
6. testing
7. documentation
8. visualization

## Repository Layout

```text
CellFlowX/
├── config/
├── data/
│   ├── raw/
│   ├── metadata/
│   └── processed/
├── docs/
│   └── adr/
├── manifests/
├── notebooks/
├── results/
├── scripts/
├── workflow/
│   ├── modules/
│   └── subworkflows/
├── streamlit_app/
├── tests/
├── docker/
├── .github/workflows/
├── main.nf
└── nextflow.config
Data Layer
data/raw/

Immutable author-provided processed 10x matrices.

These files must never be manually modified.

data/metadata/

Study and sample metadata.

data/processed/

Reproducible AnnData objects generated by CellFlowX.

Large files are excluded from Git.

Workflow Layer
main.nf

Primary Nextflow entry point.

workflow/modules/

Individual reusable workflow processes.

workflow/subworkflows/

Groups of related processes representing larger analysis stages.

Analysis Layer
scripts/

Version-controlled Python analysis implementations.

notebooks/

Exploratory analysis only.

Final production analysis must not depend exclusively on notebooks.

Configuration Layer
config/

Workflow parameters and execution profiles.

Configuration should remain separate from analysis implementation.

Results Layer
results/

Generated biological and benchmarking outputs.

Results should be reproducible from frozen inputs and workflow code.

Testing Layer
tests/

Automated validation of critical project functionality.

Presentation Layer
streamlit_app/

Interactive exploration of final CellFlowX results.

Reproducibility Principle

The final project should be reproducible from:

frozen input matrices

sample manifest
configuration
source code
container/environment specification.
